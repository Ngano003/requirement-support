# テスト用サンプルデータ

ブレークダウン機能のテスト用サンプルです。

## ファイル構成

### 1. 議事録（入力データ）
**ファイル**: `meeting-notes-library-system.md`

実際の打ち合わせで取られるような、ラフな議事録です。
- 箇条書きやメモ形式
- 不完全な情報や曖昧な表現を含む
- TODOや検討事項が残っている

**使い方**:
このファイルの内容をコピーして、ブレークダウン機能の入力欄に貼り付けてください。

### 2. 理想的な要件定義書（期待される出力）
**ファイル**: `ideal-requirements-library-system.md`

議事録から生成されるべき、理想的な要件定義書の例です。
- 構造化された形式
- 明確なセクション分け
- 不明な点は「TODO（要確認）」として明示
- 機能要件と非機能要件の分離

**使い方**:
AIが生成した要件定義書と比較して、品質を評価する際の参考としてください。

## テストシナリオ

### Step 1: 初期化
1. http://localhost:3000/breakdown にアクセス
2. `meeting-notes-library-system.md` の内容を入力欄にコピー&ペースト
3. 「要件定義を開始」ボタンをクリック

### Step 2: 生成された要件定義書を確認
左パネルに表示される要件定義書を確認：
- 構造化されているか？
- 主要な機能が抽出されているか？
- システム概要、目的、対象ユーザーが記載されているか？

### Step 3: 質問への回答
右パネルに表示される質問に回答していくことで、要件定義書がブラッシュアップされます。

**予想される質問例**:
- 「貸出冊数の上限は何冊ですか？」
- 「延滞時のペナルティはどうしますか？」
- 「雑誌やDVDも管理対象に含めますか？」
- 「返却期限リマインドは何日前に送りますか？」

**回答例**:
```
Q: 貸出冊数の上限は何冊ですか？
A: 1人あたり5冊までとします。

Q: 延滞時のペナルティはどうしますか？
A: 延滞料金は設けず、延滞が1週間以上続いた場合に督促メールを送り、
   延滞中は新規貸出を停止します。
```

### Step 4: 完成度の確認
すべての質問に答え終えたら：
- 左パネルの要件定義書が充実しているか確認
- 「TODO」や「要確認」が適切に具体化されているか確認
- 完成度スコアを確認

### Step 5: ダウンロード
完成した要件定義書をダウンロードして保存

## 期待される動作

### ✅ 良い結果
- 議事録から主要な情報が正確に抽出されている
- セクションが適切に構造化されている
- 不明な点は「TODO」として明示されている
- AIの質問が的確で、不足している情報を補える

### ❌ 改善が必要な結果
- 重要な情報が漏れている
- 構造化が不十分（セクション分けがない）
- 曖昧な表現がそのまま残っている
- 質問が的外れ、または質問が生成されない

## 備考

- このサンプルは中規模のシステム（機能数: 中程度、複雑度: 中）を想定
- より簡単な例やより複雑な例が必要な場合は、別のサンプルを参照
- 実際のテストでは、OpenRouter APIキーが必要です（`.env`に設定）
