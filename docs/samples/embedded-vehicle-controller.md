## 1. はじめに

### 1.1 目的

本文書は、次世代車載制御システムの要件を定義するものである。本システムは、電気自動車(EV)向けの統合制御システムとして、モーター制御、バッテリー管理、車両安全機能を統合的に制御する。

### 1.2 適用範囲

本要件定義書は、以下のシステムに適用される:
- メインECU(Electronic Control Unit)
- モーターコントローラー
- バッテリーマネジメントシステム(BMS)
- 車両統合制御システム

### 1.3 用語定義

| 用語 | 定義 |
|------|------|
| ECU | Electronic Control Unit。電子制御ユニット |
| BMS | Battery Management System。バッテリー管理システム |
| CAN | Controller Area Network。車載ネットワーク規格 |
| ASIL | Automotive Safety Integrity Level。自動車安全度水準 |
| SoC | State of Charge。バッテリー充電率 |
| MCU | Microcontroller Unit。マイクロコントローラユニット |
| RTOS | Real-Time Operating System。リアルタイムOS |
| OTA | Over-The-Air。無線ソフトウェア更新 |
| FOTA | Firmware Over-The-Air。ファームウェア無線更新 |

- CAN仕様書 ISO 11898

## 2. システム概要

### 2.1 システム構成

本システムは以下のサブシステムで構成される:

```
┌─────────────────────────────────────────┐
│        メインECU (主制御装置)            │
│  - ARM Cortex-R52 デュアルコア          │
│  - 統合制御ソフトウェア                 │
│  - 安全監視機能                         │
└─────────────┬───────────────────────────┘
              │ CAN-FD
    ┌─────────┼─────────┬─────────┐
    │         │         │         │
┌───▼────┐ ┌─▼──────┐ ┌▼────────┐ ┌▼────────┐
│モーター│ │  BMS   │ │インバー │ │ 診断    │
│制御ECU│ │        │ │ター制御 │ │ ECU     │
└────────┘ └────────┘ └─────────┘ └─────────┘
```

### 2.2 システム機能概要

1. **モーター制御機能**: インバーターを介した3相ACモーターの精密制御
2. **バッテリー管理機能**: リチウムイオンバッテリーの充放電制御と保護
3. **回生ブレーキ制御**: 減速時のエネルギー回収
4. **車両状態監視**: センサー情報の統合監視
5. **故障診断機能**: 自己診断とフェールセーフ処理
6. **通信機能**: CAN-FD/Ethernetによる車載ネットワーク通信

### 2.3 システム性能目標

| 項目 | 目標値 |
|------|--------|
| メイン制御周期 | 1ms |
| モーター制御周期 | 100μs |
| CAN通信周期 | 10ms |
| システム起動時間 | 500ms以内 |
| 最大消費電力 | 15W |
| 動作温度範囲 | -40℃ ~ +85℃ |

## 3. 機能要件

### 3.1 モーター制御機能

#### 3.1.1 基本制御要件

**REQ-MC-001**: システムは、3相ACモーターをベクトル制御方式で制御すること
- 制御周期: 100μs
- トルク制御精度: ±2%以内
- 応答時間: 指令値変更から10ms以内

**REQ-MC-002**: システムは、アクセルペダル開度0-100%に対して、リニアなトルク出力を実現すること
- 入力分解能: 0.1%
- 出力トルク範囲: 0-300Nm
- 非線形性: ±3%以内

**REQ-MC-003**: システムは、モーター回転数を最大15,000rpmまで制御できること
- 回転数検出分解能: 1rpm
- 制御可能範囲: 0-15,000rpm
- オーバーシュート: 3%以内

**REQ-MC-004**: システムは、モーター温度が120℃を超えた場合、出力を段階的に制限すること
- 120-130℃: 80%出力制限
- 130-140℃: 60%出力制限
- 140℃以上: 緊急停止

**REQ-MC-005**: システムは、インバーター温度を監視し、85℃を超えた場合に警告を発すること
- 温度監視周期: 100ms
- 警告閾値: 85℃
- 緊急停止閾値: 95℃

#### 3.1.2 回生ブレーキ制御

**REQ-MC-010**: システムは、減速時に回生ブレーキによる運動エネルギー回収を行うこと
- 回生効率: 70%以上
- 最大回生トルク: -100Nm
- 回生開始車速: 5km/h以上

**REQ-MC-011**: システムは、バッテリーSoCが95%以上の場合、回生ブレーキを制限すること
- 95-98%: 50%制限
- 98-100%: 回生停止

**REQ-MC-012**: システムは、回生ブレーキと機械ブレーキを協調制御すること
- ブレーキペダル踏力に応じた配分制御
- 回生不足分を機械ブレーキで補完
- 切替時のショック: 0.1G以下

### 3.2 バッテリー管理機能

#### 3.2.1 充放電制御

**REQ-BMS-001**: システムは、バッテリーパックの充放電を制御すること
- セル数: 96セル直列
- 公称電圧: 355.2V (96セル × 3.7V)
- 最大充電電流: 150A
- 最大放電電流: 400A

**REQ-BMS-002**: システムは、各セルの電圧を個別に監視すること
- 監視周期: 100ms
- 電圧測定精度: ±5mV
- 異常検出閾値: セル電圧差 200mV以上

**REQ-BMS-003**: システムは、バッテリー温度を監視し、適切な温度範囲を維持すること
- 動作温度範囲: 10℃~45℃
- 温度センサー数: 24個(4セルあたり1個)
- 温度測定精度: ±1℃

**REQ-BMS-004**: システムは、SoC(充電率)を推定し、運転者に表示すること
- 推定精度: ±3%
- 更新周期: 1秒
- 推定方式: 電流積算+開放電圧法

**REQ-BMS-005**: システムは、SoHまたはバッテリー劣化状態を推定すること
- 推定周期: 充電完了時
- 推定パラメータ: 内部抵抗、容量低下率
- 劣化警告閾値: 初期容量の80%以下

#### 3.2.2 セルバランシング

**REQ-BMS-010**: システムは、セル間電圧差を是正するためのバランシング機能を持つこと
- バランシング方式: パッシブ方式
- バランシング電流: 最大200mA/セル
- バランシング条件: セル電圧差100mV以上

**REQ-BMS-011**: システムは、充電中にバランシングを実施すること
- 実施タイミング: SoC 80%以上
- 完了条件: セル電圧差50mV以下
- タイムアウト: 4時間

#### 3.2.3 保護機能

**REQ-BMS-020**: システムは、過充電を検出し、充電を遮断すること
- セル過充電閾値: 4.25V
- 遮断時間: 検出から50ms以内
- 復帰条件: 全セル4.15V以下

**REQ-BMS-021**: システムは、過放電を検出し、放電を遮断すること
- セル過放電閾値: 2.5V
- 遮断時間: 検出から50ms以内
- 復帰条件: 充電により全セル2.8V以上

**REQ-BMS-022**: システムは、過電流を検出し、電流を遮断すること
- 充電過電流閾値: 200A
- 放電過電流閾値: 500A
- 検出時間: 100ms継続
- 遮断時間: 検出から20ms以内

**REQ-BMS-023**: システムは、短絡を検出し、即座に電流を遮断すること
- 短絡検出閾値: 1000A
- 遮断時間: 検出から5ms以内
- 遮断手段: メインリレー開放

**REQ-BMS-024**: システムは、異常温度を検出し、適切な保護動作を行うこと
- 高温警告: 50℃
- 高温遮断: 60℃
- 低温警告: 0℃
- 低温充電禁止: 0℃以下

### 3.3 車両統合制御機能

#### 3.3.1 駆動力制御

**REQ-VIC-001**: システムは、運転者の操作入力を統合的に処理し、最適な駆動力を出力すること
- 入力: アクセルペダル、ブレーキペダル、シフトポジション
- 出力: モータートルク指令値
- 演算周期: 10ms

**REQ-VIC-002**: システムは、路面状況に応じてトラクション制御を行うこと
- スリップ率検出: 前後輪速度差から算出
- スリップ率目標値: 10%以下
- トルク低減量: 最大50%まで段階的に制限

**REQ-VIC-003**: システムは、急加速時のホイールスピンを抑制すること
- スピン検出閾値: スリップ率15%以上
- 介入時間: 検出から30ms以内
- トルク低減率: 20%/100ms

#### 3.3.2 走行モード制御

**REQ-VIC-010**: システムは、複数の走行モードを提供すること
- エコモード: 最大トルク200Nm、回生ブレーキ強
- ノーマルモード: 最大トルク300Nm、回生ブレーキ中
- スポーツモード: 最大トルク300Nm、アクセルレスポンス向上

**REQ-VIC-011**: システムは、運転者の操作により走行モードを切り替え可能とすること
- 切替方法: モード切替スイッチ
- 切替時間: 200ms以内
- 切替条件: 車両停止時または低速走行時(20km/h以下)

**REQ-VIC-012**: システムは、選択中の走行モードをメーター表示すること
- 表示方法: メーター内インジケーター
- 表示更新周期: 100ms

#### 3.3.3 クルーズ制御

**REQ-VIC-020**: システムは、定速走行制御(クルーズコントロール)機能を提供すること
- 設定可能速度範囲: 30-120km/h
- 速度維持精度: ±2km/h
- 制御周期: 50ms

**REQ-VIC-021**: システムは、クルーズ制御中にブレーキ操作を検出した場合、制御を解除すること
- 検出条件: ブレーキペダルストローク 5mm以上
- 解除時間: 検出から50ms以内
- 解除方法: トルク指令値を0に設定

### 3.4 安全機能

#### 3.4.1 フェールセーフ機能

**REQ-SAFE-001**: システムは、重大な故障を検出した場合、安全な状態に遷移すること
- フェールセーフモード: リンプホームモード(最大速度40km/h)
- 遷移時間: 故障検出から500ms以内
- 遷移条件: ASIL-D故障の検出

**REQ-SAFE-002**: システムは、センサー異常を検出した場合、冗長センサーに切り替えること
- 対象センサー: アクセルペダルセンサー(2系統)
- 異常判定: 2系統の値の差が10%以上
- 切替時間: 異常検出から50ms以内

**REQ-SAFE-003**: システムは、制御系の異常を検出した場合、予備系に切り替えること
- 対象: メインECUデュアルコア
- 切替条件: メインコアのウォッチドッグタイムアウト
- 切替時間: タイムアウト検出から100ms以内

**REQ-SAFE-004**: システムは、通信異常を検出した場合、安全側の制御を行うこと
- 対象通信: CAN-FD
- 異常判定: 通信タイムアウト(100ms)
- 安全動作: モータートルク指令値0、機械ブレーキ要求

**REQ-SAFE-005**: システムは、電源異常を検出した場合、重要データを不揮発メモリに保存すること
- 検出条件: 電源電圧9V以下
- 保存データ: 故障コード、走行距離、バッテリー情報
- 保存時間: 検出から50ms以内に完了

#### 3.4.2 診断機能

**REQ-DIAG-001**: システムは、起動時に自己診断を実施すること
- 診断項目: RAM、ROM、センサー、アクチュエーター
- 診断時間: 500ms以内
- 異常時動作: 故障コード記録、起動中止

**REQ-DIAG-002**: システムは、運転中に周期的な自己診断を実施すること
- 診断周期: 100ms
- 診断項目: センサー値の妥当性、通信正常性、制御演算結果
- 異常時動作: 故障コード記録、フェールセーフ遷移

**REQ-DIAG-003**: システムは、検出した故障情報を不揮発メモリに記録すること
- 記録内容: 故障コード、発生時刻、走行距離、環境条件
- 記録容量: 最新100件
- 記録形式: ISO 14229準拠DTC

**REQ-DIAG-004**: システムは、外部診断装置からの故障コード読み出しに対応すること
- 通信プロトコル: ISO 14229 UDS
- 対応サービス: ReadDTC、ClearDTC、ReadDataByID
- 通信インターフェース: CAN

**REQ-DIAG-005**: システムは、外部診断装置からのアクチュエーター動作テストに対応すること
- テスト項目: モーター駆動、リレー動作、警告灯点灯
- 実施条件: 車両停止、シフトP位置
- 安全措置: 最大出力10%制限

#### 3.4.3 機能安全要件

**REQ-FS-001**: システムは、ISO 26262のASIL-Dレベルを満たすこと
- 対象機能: モーター制御、ブレーキ制御
- 安全メカニズム: デュアルコア、センサー冗長化、プロセス監視

**REQ-FS-002**: システムは、ソフトウェアの実行を監視するウォッチドッグ機能を持つこと
- 方式: 独立ハードウェアウォッチドッグ
- タイムアウト時間: 100ms
- ウィンドウ方式: 80-100msのウィンドウ期間内にクリア

**REQ-FS-003**: システムは、メモリの整合性を監視すること
- 対象: プログラムROM、制御データRAM
- 方式: CRC32チェックサム
- 周期: ROM=起動時、RAM=100ms毎

**REQ-FS-004**: システムは、制御演算結果の妥当性を検証すること
- 検証項目: トルク指令値の範囲、変化率
- 範囲チェック: -100Nm ~ +300Nm
- 変化率チェック: 100Nm/100ms以下

**REQ-FS-005**: システムは、ASIL分解により、一部機能をASIL-B(QM)とすること
- ASIL-D: モーター制御、ブレーキ制御、バッテリー保護
- ASIL-B: 走行モード切替、メーター表示
- QM: 診断記録、統計情報

### 3.5 通信機能

#### 3.5.1 CAN通信

**REQ-COM-001**: システムは、CAN-FD通信により車載ネットワークと接続すること
- 通信速度: データフェーズ 2Mbps、仲裁フェーズ 500kbps
- バス終端: 120Ω終端抵抗
- コネクタ: TE Connectivity製 MCP 1.5シリーズ

**REQ-COM-002**: システムは、以下のCAN信号を送信すること
- モータートルク実績値: 10ms周期
- モーター回転数: 10ms周期
- バッテリーSoC: 100ms周期
- バッテリー電圧/電流: 100ms周期
- システム状態: 100ms周期
- 故障情報: イベント駆動

**REQ-COM-003**: システムは、以下のCAN信号を受信すること
- アクセルペダル開度: 10ms周期
- ブレーキペダル踏力: 10ms周期
- シフトポジション: 20ms周期
- 車速情報: 10ms周期
- 走行モード指令: イベント駆動

**REQ-COM-004**: システムは、CAN通信のタイムアウトを検出すること
- タイムアウト時間: 受信周期の3倍
- 検出時動作: 故障コード記録、フェールセーフ値使用
- 復帰条件: 正常な信号を3回連続受信

**REQ-COM-005**: システムは、CAN信号に異常値を検出した場合、使用を停止すること
- 異常判定: 信号範囲外、変化率異常、CRCエラー
- 検出時動作: 前回値保持または安全側固定値使用
- 異常回数閾値: 連続3回または累積10回

#### 3.5.2 Ethernet通信

**REQ-COM-010**: システムは、Ethernet通信により診断装置と接続すること
- 通信規格: 100BASE-TX
- プロトコル: DoIP (Diagnostics over IP)
- コネクタ: RJ45

**REQ-COM-011**: システムは、Ethernetを介したファームウェア更新に対応すること
- 更新方式: フラッシュメモリ書き換え
- 更新サイズ: 最大8MB
- 更新時間: 10分以内

### 3.6 電源管理機能

**REQ-PWR-001**: システムは、12V車載電源から動作電源を生成すること
- 入力電圧範囲: 9V ~ 16V
- 出力電圧: 5V(デジタル系)、3.3V(MCU)
- 電源効率: 85%以上

**REQ-PWR-002**: システムは、イグニッション信号により起動・停止すること
- 起動条件: イグニッションON
- 停止条件: イグニッションOFF後30秒
- スリープ移行時間: イグニッションOFF検出から30秒以内

**REQ-PWR-003**: システムは、低電圧を検出し、システムを保護すること
- 低電圧警告: 10V
- 低電圧シャットダウン: 9V
- 復帰電圧: 10.5V(ヒステリシス)

**REQ-PWR-004**: システムは、スリープモード時に低消費電力動作を行うこと
- スリープ時消費電流: 5mA以下
- ウェイクアップ条件: CAN信号受信、イグニッションON
- ウェイクアップ時間: 信号検出から500ms以内

### 3.7 データロギング機能

**REQ-LOG-001**: システムは、運転データを記録すること
- 記録データ: 車速、トルク、バッテリーSoC、電力消費
- 記録周期: 1秒
- 記録容量: 最新24時間分

**REQ-LOG-002**: システムは、異常発生時のデータを記録すること
- 記録タイミング: 故障コード記録時
- 記録データ: 異常発生前後10秒間の制御データ
- 記録件数: 最新10件

**REQ-LOG-003**: システムは、記録データを外部診断装置から読み出し可能とすること
- 読出方法: UDSプロトコル ReadDataByID
- データ形式: バイナリ形式
- 転送速度: 最低100kbps

## 4. 非機能要件

### 4.1 性能要件

**REQ-PERF-001**: システムは、リアルタイム性を確保すること
- モーター制御タスク: 100μs周期、ジッター±10μs以内
- 統合制御タスク: 1ms周期、ジッター±100μs以内
- 通信タスク: 10ms周期、ジッター±1ms以内

**REQ-PERF-002**: システムは、CPUリソースに余裕を持つこと
- 平均CPU使用率: 60%以下
- 最大CPU使用率: 80%以下
- 測定条件: 最大負荷時

**REQ-PERF-003**: システムは、メモリリソースに余裕を持つこと
- RAM使用率: 70%以下
