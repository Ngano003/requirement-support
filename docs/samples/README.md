  - レビュー画像の制限

- 🟢 **アクセス権限の詳細が不十分**

### 3. 車載制御システム（組み込み・大規模）
**ファイル**: [embedded-vehicle-controller.md](embedded-vehicle-controller.md)

**概要**: 電気自動車向けの車載制御システム（モーター制御・バッテリー管理・安全機能）の要件定義書

**規模**: 約830行、大規模

**機能範囲**:
- モーター制御機能（ベクトル制御、回生ブレーキ）
- バッテリー管理機能（BMS、セルバランシング、保護機能）
- 車両統合制御機能（駆動力制御、走行モード、クルーズ制御）
- 安全機能（フェールセーフ、診断、機能安全ASIL-D）
- 通信機能（CAN-FD、Ethernet）
- ISO 26262準拠の機能安全要件

**意図的に埋め込んだ問題点**:

#### 🔴 重大度:高（5つ）

1. **REQ-MC-012とブレーキ制御の抜け漏れ**
   - 回生ブレーキと機械ブレーキの協調制御について記載があるが、機械ブレーキ制御の詳細要件が存在しない
   - 影響: 安全性に直結する制動システムの要件が不完全

2. **REQ-BMS-004とREQ-BMS-005の一貫性欠如**
   - BMS-005でSoH（バッテリー健全性）推定について記載があるが、BMS-004ではSoC推定のみ記載
   - SoHの運転者への表示要件が抜けている
   - 影響: バッテリー劣化状態を運転者が把握できない

3. **REQ-SAFE-003のデュアルコア構成の抜け漏れ**
   - メインECUデュアルコアの切替について記載があるが、デュアルコア構成の詳細（マスター/スレーブ構成、同期方式、負荷分散など）が全く定義されていない
   - 影響: ASIL-D対応の冗長系設計が不明確

4. **REQ-MC-002とREQ-VIC-010のトルク出力範囲の矛盾**
   - MC-002では0-300Nm、VIC-010のエコモードでは最大200Nm、ノーマル/スポーツでは300Nmと記載
   - モード間の調整メカニズムや優先度が不明
   - 影響: 実装時に仕様解釈が分かれる可能性

5. **REQ-BMS-001とREQ-BMS-022の保護マージン不明**
   - 最大放電電流400Aと記載があるが、過電流閾値が500A
   - 正常動作範囲と異常検出閾値の設計マージンが明記されていない
   - 影響: 保護機能の設計根拠が不明確

#### 🟡 重大度:中（5つ）

6. **REQ-VIC-021のクルーズ制御解除時の乗り心地**
   - 「トルク指令値を0に設定」とあるが、急激なトルク変化による乗り心地への影響やランプ制御の必要性について記載がない
   - 影響: ユーザー体験の品質低下

7. **REQ-PWR-003の高電圧保護の抜け漏れ**
   - 低電圧保護について記載があるが、高電圧保護（過電圧）の要件が抜けている
   - 影響: 過電圧時の機器保護が不十分

8. **REQ-HW-011とREQ-MC-005の保護協調の欠如**
   - 電流センサー測定範囲±600A、インバーター温度監視85℃警告とあるが、過電流時の温度上昇との相関関係や保護協調が定義されていない
   - 影響: 複合的な異常時の動作が不明

9. **REQ-DIAG-003の上書きポリシー不明**
   - 故障コードを最新100件記録とあるが、記録容量が不足した場合の上書きポリシー（FIFO等）が明記されていない
   - 影響: 古い重要な故障情報が失われる可能性

10. **REQ-SW-041のデフォルト値管理の抜け漏れ**
    - キャリブレーションデータ整合性チェック失敗時に「デフォルト値使用」とあるが、そのデフォルト値の定義や管理方法が記載されていない
    - 影響: フェールセーフ動作の信頼性が不明

#### 🟢 重大度:低（5つ）

11. **REQ-LOG-001のメモリ容量見積もり不足**
    - 運転データを最新24時間分記録、記録周期1秒とあるが、データサイズやメモリ容量の見積もりが記載されていない
    - 影響: メモリ設計時に追加検討が必要

12. **REQ-USE-001の警告レベル判定基準不明**
    - 警告レベルを3段階（情報、警告、重大）と定義しているが、各レベルの具体的な判定基準が記載されていない
    - 影響: 実装時に判断が必要

13. **REQ-COM-005の変化率閾値不明**
    - CAN信号の異常判定基準に「変化率異常」が含まれているが、具体的な変化率の閾値が定義されていない
    - 影響: テスト項目が確定できない

14. **REQ-MAINT-002の更新異常時動作不明**
    - OTA更新のロールバック機能について記載があるが、更新中の電源断などの異常時の動作が明記されていない
    - 影響: 異常時の復旧手順が不明

15. **REQ-HW-031の消費電力配分不明**
    - ECU筐体の放熱性能で許容損失50Wと記載があるが、各サブシステム（MCU、電源、通信モジュールなど）ごとの消費電力配分が記載されていない
    - 影響: 詳細設計時に熱設計の見直しが必要な可能性

**推奨用途**:
- 組み込みシステムの要件定義レビュー体験
- 機能安全要件を含む複雑なシステムのレビュー
- 一貫性チェック機能のテスト（数値の矛盾検出など）

### 4. スマートビルディング管理システム（IoT・大規模）
**ファイル**: [iot-smart-building.md](iot-smart-building.md)

**概要**: オフィスビル向けスマートビルディング統合管理システム（空調・照明・セキュリティ・エネルギー管理）の要件定義書

**規模**: 約900行、大規模

**機能範囲**:
- IoTゲートウェイ機能（BLE、LoRaWAN、Zigbee通信）
- センサーノード機能（温湿度、CO2、人感、電力）
- アクチュエーター制御（空調、照明、ブラインド）
- エネルギー管理機能（BEMS）
- セキュリティ機能（入退室、監視カメラ、異常検知）
- AI・予測分析機能
- 約1,500台のIoTデバイス管理

**意図的に埋め込んだ問題点**:

#### 🔴 重大度:高（5つ - 抜け漏れと矛盾）

**【抜け漏れ】**

1. **REQ-GW-022とREQ-GW-005のデータ保存容量の不整合**
   - GW-022: ゲートウェイ稼働状態を5分毎に報告、15分間応答なしで異常判定
   - GW-005: ネットワーク断時に最大24時間分のデータをローカル保存
   - **問題**: 24時間分のセンサーデータ（500台×1分周期×24時間=72万レコード）を保存するストレージ容量が未定義
   - 影響: ゲートウェイのストレージ設計が不可能

2. **REQ-AC-004の換気制御における窓開閉制御装置の要件欠如**
   - CO2濃度に基づく換気制御で「窓開閉制御」と記載があるが、窓開閉アクチュエーターに関する要件が一切存在しない
   - **問題**: 制御対象デバイスの仕様、通信方式、安全機能（強風時の自動閉鎖など）が未定義
   - 影響: 重要な制御機能が実装不可能

3. **REQ-SEC-012の顔認証とREQ-SEC-001のICカード認証の統合仕様欠如**
   - SEC-001: ICカードによる入退室管理
   - SEC-012: 顔認証機能
   - **問題**: 両方の認証方式をどう統合するか（併用、選択、二要素認証など）の記載が全くない
   - 影響: セキュリティ設計の根幹が不明確

**【矛盾】**

4. **REQ-SN-002とREQ-SN-011の送信周期の矛盾**
   - SN-002: 温湿度センサーノードは1分周期で送信
   - SN-011: CO2センサーノードは5分周期で送信（高濃度時は1分周期に変更）
   - REQ-GW-002: ゲートウェイは収集したセンサーデータを1分間隔でバッチ送信
   - **問題**: CO2センサーの5分周期データをどうバッチ送信するのか、仕様が矛盾
   - 影響: データ収集ロジックの設計が困難

5. **REQ-PERF-002とREQ-SCALE-001のデバイス数の矛盾**
   - PERF-002: 同時接続デバイス数 2,000台
   - SCALE-001: 初期構成1,500台、拡張可能数5,000台まで
   - REQ-GW-001: ゲートウェイあたり最大500台接続
   - **問題**: 2,000台接続時は最低4台のゲートウェイが必要だが、システム構成図では4台のゲートウェイしか記載がなく、5,000台への拡張時の構成が不明
   - 影響: スケーラビリティ設計に矛盾

#### 🟡 重大度:中（5つ - 抜け漏れと矛盾）

**【抜け漏れ】**

6. **REQ-GW-020のOTA更新失敗時のロールバック詳細不足**
   - 「更新失敗時に自動復帰」とあるが、失敗判定の基準（起動失敗、動作異常、通信断など）や復帰手順の詳細が記載されていない
   - 影響: OTA更新の信頼性設計が不十分

7. **REQ-SECURITY-001のパスワードポリシーと多要素認証の詳細不足**
   - 「90日毎に変更」とあるが、変更強制の実装方法や、多要素認証が必須か任意かが不明
   - 影響: セキュリティ実装の詳細が確定できない

8. **REQ-EM-012のテナント別計測におけるサブメーター設置要件の欠如**
   - テナント別のエネルギー使用量を表示するとあるが、テナント別に電力を計測するサブメーターの設置場所、数量、仕様が未定義
   - 影響: テナント別課金の根拠となる計測インフラが不明

**【矛盾】**

9. **REQ-UI-013とREQ-SEC-001の入退室認証方式の矛盾**
   - SEC-001: ICカードによる入退室管理、認証時間0.5秒以内
   - UI-013: スマートフォンをカードキー代わりに使用、BLE + 生体認証
   - **問題**: スマートフォン認証（BLE接続+生体認証）で0.5秒以内の認証が技術的に困難
   - 影響: 認証時間要件の見直しが必要

10. **REQ-SN-003とREQ-SN-031の電源方式の矛盾**
    - SN-003: 温湿度センサーノードは電池駆動、電池寿命3年以上
    - SN-031: 電力センサーノードは10秒周期で送信、送信プロトコルは有線LAN（Ethernet）またはRS-485
    - **問題**: 有線LANまたはRS-485接続なら電源供給可能なはずだが、電源仕様が未記載
    - 影響: 電力センサーノードの設計仕様が不明確

#### 🟢 重大度:低（5つ - 抜け漏れ）

11. **REQ-AI-002の在室人数予測の精度基準未定義**
    - 在室人数を予測するとあるが、予測精度の目標値（誤差±何%など）が記載されていない
    - 影響: AI予測機能の評価基準が不明

12. **REQ-AVAIL-003のバックアップからのリストア手順未定義**
    - バックアップ頻度と保存期間は記載されているが、実際の復旧手順やリストア時間が未定義
    - 影響: 災害復旧計画の詳細化が必要

13. **REQ-LT-003の照度センサーによる自然光考慮の具体的アルゴリズム未定義**
    - 「自然光を考慮」とあるが、具体的な調光アルゴリズム（窓際と内側の調光比率など）が未定義
    - 影響: 照明制御ロジックの実装詳細が不明

14. **REQ-TEST-022のSUSスコア測定方法の詳細不足**
    - SUSスコア70以上という基準はあるが、測定タイミング、被験者の属性、評価項目が不明
    - 影響: ユーザビリティテストの実施方法が確定できない

15. **REQ-CONST-020の投資回収期間5年の根拠未定義**
    - 投資回収期間5年以内とあるが、省エネ効果による削減金額の試算や計算根拠が記載されていない
    - 影響: 費用対効果の検証ができない

**推奨用途**:
- IoTシステムの要件定義レビュー体験
- 大規模デバイス管理システムのレビュー
- クラウド・エッジ連携システムの一貫性チェック
- データフロー整合性の検証

## 💡 Tips

### レビュー結果の活用方法

1. **指摘事項の優先度で分類**
   - High（重大）: すぐに対応が必要
   - Medium（中程度）: 計画的に対応
   - Low（軽微）: 余裕があれば対応

2. **カテゴリ別に対応**
   - 漏れ: 不足している要件を追加
   - 矛盾: 整合性を確認して修正
   - 曖昧: 具体的な表現に書き換え
   - 品質: 読みやすさ・保守性の向上

3. **改善提案を参考に修正**
   - AIが提示する具体的な改善案を参考にする
   - 同様の問題が他の箇所にもないかチェック
