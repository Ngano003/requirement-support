## 4. Phase 1: 基本アーキテクチャ（MVP）

### 4.1 レイヤー構成

```
┌─────────────────────────────────────────┐
│         プレゼンテーション層              │
│  - Next.js コンポーネント                │
│  - ルーティング                          │
│  - UIロジック                            │
└────────────┬────────────────────────────┘
             │ HTTP/JSON
┌────────────▼────────────────────────────┐
│         APIレイヤー                      │
│  - FastAPI エンドポイント                │
│  - リクエスト/レスポンス処理              │
│  - バリデーション                        │
└────────────┬────────────────────────────┘
             │
┌────────────▼────────────────────────────┐
│       ビジネスロジック層                  │
│  - Breakdown Service                    │
│  - Review Service                       │
│  - Session Manager                      │
└────────────┬────────────────────────────┘
             │
┌────────────▼────────────────────────────┐
│        外部サービス層                     │
│  - LLM Service (OpenRouter/vLLM)        │
│  - File System (データ永続化)            │
└─────────────────────────────────────────┘
```

### 4.2 コンポーネント間通信

#### フロントエンド → バックエンド
- プロトコル: HTTP/REST
- フォーマット: JSON
- 認証: なし (Phase 1)
- CORS: 許可されたオリジンのみ

#### バックエンド → LLM
- プロトコル: HTTP
- API: OpenAI互換
- ストリーミング: 非サポート (Phase 1)

### 4.3 データ永続化戦略

#### セッションデータ
- 保存場所: `data/sessions/{session_id}.json`
- フォーマット: JSON
- 内容:
  - セッションID
  - 入力テキスト
  - 要件定義書
  - 質問リスト
  - 回答履歴
  - 充足率

#### 要件定義書
- 保存場所: `data/requirements/{session_id}.md`
- フォーマット: Markdown
- 更新タイミング: 各回答後

## 6. データフロー

### 6.1 ブレークダウン機能のデータフロー

```
[ユーザー] 打ち合わせ記録を入力
    ↓
[Frontend] POST /api/breakdown/initialize
    ↓
[Backend] BreakdownService.initialize_session()
    ↓
[LLM] 要件定義書のたたき台を生成
    ↓
[LLM] 質問リストを生成
    ↓
[Backend] セッションを保存 (data/sessions/)
[Backend] 要件定義書を保存 (data/requirements/)
    ↓
[Frontend] 要件定義書と質問を表示
    ↓
[ユーザー] 質問に回答
    ↓
[Frontend] POST /api/breakdown/answer
    ↓
[Backend] BreakdownService.process_answer()
    ↓
[LLM] 要件定義書を更新
[LLM] 新しい質問を生成
    ↓
[Backend] セッションを更新
[Backend] 要件定義書を更新
[Backend] (Phase 2) Git自動コミット
    ↓
[Frontend] 更新された要件定義書と新しい質問を表示
    ↓
[繰り返し]
```

### 6.2 レビュー機能のデータフロー

```
[ユーザー] 要件定義書を入力
    ↓
[Frontend] POST /api/review
    ↓
[Backend] ReviewService.review_requirements()
    ↓
[LLM] 要件定義書を分析
    ↓
[LLM] 指摘事項とスコアを生成
    ↓
[Backend] (Phase 2) グラフ構築
    ↓
[Neo4j] (Phase 2) 知識グラフ作成
    ↓
[Neo4j] (Phase 2) Cypherクエリで分析
    ↓
[Backend] (Phase 2) グラフ分析結果をLLMに渡す
    ↓
[LLM] (Phase 2) 強化されたレビューレポート生成
    ↓
[Frontend] レビュー結果を表示
```

## 7. API設計

### 7.1 RESTful API原則

- リソースベースのURL設計
- HTTPメソッドの適切な使用（GET, POST, PUT, DELETE）
- ステータスコードの適切な使用
- JSON形式のリクエスト/レスポンス

### 7.2 エンドポイント一覧

#### Phase 1 (MVP)

| メソッド | エンドポイント | 説明 |
|---------|--------------|------|
| POST | /api/breakdown/initialize | ブレークダウン初期化 |
| POST | /api/breakdown/answer | 質問への回答処理 |
| GET | /api/breakdown/status/{session_id} | セッション状態取得 |
| POST | /api/review | 要件定義書レビュー |

#### Phase 2 (拡張)

| メソッド | エンドポイント | 説明 |
|---------|--------------|------|
| POST | /api/graph/build | 知識グラフ構築 |
| GET | /api/graph/analyze/{session_id} | グラフ分析実行 |
| GET | /api/graph/visualize/{session_id} | グラフ可視化データ取得 |
| POST | /api/review/enhanced | GraphRAG強化レビュー |
| GET | /api/version/history/{session_id} | バージョン履歴取得 |
| GET | /api/version/diff/{session_id} | 差分表示 |
| POST | /api/version/revert/{session_id} | バージョン復元 |

### 7.3 エラーハンドリング

#### HTTPステータスコード

- 200: 成功
- 400: バリデーションエラー
- 404: リソースが見つからない
- 500: サーバーエラー

#### エラーレスポンス形式

```json
{
  "detail": "エラーメッセージ",
  "error_code": "ERROR_CODE",
  "timestamp": "2025-11-10T10:30:00Z"
}
```

#### アプリケーションログ
